## 2. NFC and QR technical facts (for plain-English copy)
- NTAG213/215/216 are NFC Forum Type 2 tag chips with 144 / 504 / 888 bytes of user memory. [https://nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf]
- Datasheet: operating distance up to 100 mm (depends on reader/antenna), data retention 10 years, write endurance 100,000 cycles, optional read-only locking and 32-bit password protection. [https://nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf]
- (inference) For "tap to review" a URL needs well under 144 bytes, so NTAG213 is enough; larger chips add nothing for a link. Say "a few centimetres", not 10cm.
- No battery: tag is read by the phone's field (passive). (inference from standard NFC tag behaviour; datasheet describes a passive tag IC but the extracted text did not use that word in the lines I checked.) [https://nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf]
- iPhone: Apple's Core NFC talk says background tag reading is new on iPhone XS, XS Max and XR; it works whenever the screen is on after first unlock, and needs an NDEF URL record. [https://developer.apple.com/videos/play/tech-talks/702]
- NFC Forum and press coverage of the same 2018 change: no app required on those models. [https://nfc-forum.org//coverage/new-2018-iphones-support-background-nfc-tag-reading-no-app-required]
- Older iPhones (7/8/X) reportedly need Control Centre/app; one consumer guide says so, Apple material did not confirm it. Treat as unverified. [https://gototags.com/articles/how-to-use-nfc-tags-with-an-iphone-ios]
- Android: Settings > Connected devices > Connection preferences > NFC (labels vary by maker). Seen on carrier guides, not Google's own page (official Google page not located). [https://deviceguides.vodafone.co.uk/google/pixel-9-android-14/connectivity/turn-nfc-on-or-off/]
- Seller overclaims to avoid: "works with all phones" / "100% compatible" contradict sellers' own FAQs. [https://www.tapreviewcards.co.uk/] [https://evrycard.co.uk/nfc-business-cards/]
- Static vs dynamic QR: static encodes the destination in the pattern, cannot be edited, has no scan analytics and does not expire; dynamic encodes a redirect link so the destination can be changed after printing and can offer tracking/expiry. [https://help.hovercode.com/article/7-static-vs-dynamic-qr-codes]
- If the link changes: a static QR or an NFC tag holding the old URL keeps pointing at the old URL until re-written (NFC tags are rewritable up to 100,000 cycles unless locked) or the URL itself redirects. [https://nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf]
- (inference) Safest offer: encode a stable URL we control or the customer's own short link, say plainly "if your review link changes, we can reprogram/reprint" and lock tags only on request.
- What happens to a dynamic QR when a provider's subscription lapses: no source found; vendor-specific. (Not found.)
- Google's review link steps and QR are only generated on a computer browser, not mobile. [https://support.google.com/business/answer/16816815]

## 3. Google review links and policy
- Official route: Business Profile (business.google.com) > Read reviews > Get more reviews > copy link or save QR code; also share via email/WhatsApp/Facebook. [https://support.google.com/business/answer/16816815]
- The help page does not state the URL format. Secondary guides say Google generates `g.page/r/<ID>/review`. [https://support.google.com/business/answer/16816815] [https://wpsocialninja.com/google-review-link-generator/]
- `https://search.google.com/local/writereview?placeid=<PLACE_ID>` is described by guides as undocumented by Google; a 2026 forum thread reports HTTP 400 for one business while the share link worked. [https://community.make.com/t/anyone-successfully-using-google-review-deep-links-in-2026-getting-400-errors/108466]
- Google's Place ID docs: place IDs may change; old ones can return NOT_FOUND; refresh IDs older than 12 months. They do not mention the writereview URL. [https://developers.google.com/maps/documentation/places/web-service/place-id]
- (inference) Ask customers to paste the g.page link from their own Business Profile (or have them send it) rather than deriving a placeid link ourselves.
- Policy: incentives (free/discounted goods, payment) for reviews are prohibited, including incentives to change/remove a review. [https://support.google.com/contributionpolicy/answer/7400114]
- Policy: merchants must not discourage or prohibit negative reviews, must not require or pressure reviews on premises, and must not request specific content; encouraging genuine reviews without incentives is allowed. [https://support.google.com/contributionpolicy/answer/7400114]
- The policy page does not use the term "review gating"; closest rule is the ban on selectively soliciting positive reviews. [https://support.google.com/contributionpolicy/answer/7400114]
- (inference) Our copy must not promise "more 5-star reviews", "boost rankings", or a private-feedback screen before the Google link. **[REVIEW]**

## 4. Wi-Fi QR string
- Format: `WIFI:T:<WPA|WEP|nopass>;S:<ssid>;P:<password>;H:<true|false optional>;;` Fields are semicolon-separated and the payload ends with two semicolons. [https://quickchart.io/documentation/qr-codes/wifi-qr-codes/]
- Escape backslash, semicolon, comma, colon and double quote with a backslash (e.g. password `p;ss` becomes `p\;ss`). [https://inventivehq.com/blog/how-do-i-create-a-wifi-qr-code-for-easy-network-sharing]
- Empty SSID is invalid (SSID 1-32 chars); open networks leave password empty; a trailing newline breaks scanning; URL-encode only if embedding in a URL. [https://inventivehq.com/blog/how-do-i-create-a-wifi-qr-code-for-easy-network-sharing]
- The ZXing reference page for this format could not be fetched (HTTP 504), so the formal spec was not directly read. [https://github.com/zxing/zxing/wiki/Barcode-Contents]
- Security (inference): the password sits in the QR in readable form; anyone who photographs it has it. Advise a separate guest network, rotate the password, never use the main/office network. A new password needs a reprint: one seller's own FAQ says so. [https://www.faire.com/product/p_4tkmnftv6d]

## 5. UK law and costs (all **[REVIEW]** before launch)
- Consumer Contracts Regulations 2013, reg 28(1)(b): the right to cancel does not apply to "the supply of goods that are made to the consumer's specifications or are clearly personalised". [https://www.legislation.gov.uk/uksi/2013/3134/regulation/28]
- (inference) CCR protects consumers only; business buyers have no statutory cooling-off period, so the terms must be contractual. Our online form should distinguish consumer vs business buyer, and the exemption notice must be shown before purchase.
- Consumer Rights Act 2015 s.28: unless agreed otherwise, delivery without undue delay and in any event within 30 days of the contract; if missed the consumer can set a further deadline then end the contract and get a full refund, or end at once if timing was essential. [https://www.legislation.gov.uk/ukpga/2015/15/section/28]
- CRA s.22: short-term right to reject faulty goods, default 30 days from the latest of ownership/possession, delivery or installation. Personalisation does not remove this for faulty goods (inference; s.22 text read, personalisation interaction not separately sourced). [https://www.legislation.gov.uk/ukpga/2015/15/section/22]
- VAT: gov.uk states mandatory registration when taxable turnover exceeds £90,000; the page fetched gave no 2026/27 date. Third-party sites say £90,000 is unchanged for 2026/27 and deregistration is £88,000 (one site says £83,000, treated as an error). [https://www.gov.uk/vat-registration-thresholds] [https://zmartly.co.uk/news-insights/when-do-i-need-to-register-for-vat]
- Price display: a trading standards note says consumer prices must include VAT, with exemption for sales only to businesses, and mandatory extra charges (delivery) must be included or shown with equal prominence. Note predates DMCC Act; confirm on gov.uk/CMA. [https://cms.pembrokeshire.gov.uk/trading-standards-information/providing-price-information]
- DMCC Act 2024 bans drip pricing: total price including mandatory fees must be shown clearly; CMA reported first fines in April 2026 (commentary, not primary). [https://www.winstontaylor.com/insights/cma-gets-serious-on-dmcca-price-transparency-requirements]
- (inference) If we are not VAT-registered we show the same price with no VAT line; if/when registered, prices shown to consumers must include VAT. Also decide whether a shipping line is mandatory (it is, so show it before the checkout page).
- Royal Mail from 7 April 2026: Tracked 48 online prices large letter up to 750g £2.85, small parcel up to 2kg £3.65; Tracked 24 £3.80 / £4.65 (as summarised from Royal Mail's pricing page via search; the page itself returned 403). [https://www.royalmail.com/prices2026]
- 2nd-class stamp large letter 0-100g £1.55 and small parcel 0-2kg £4.25 per a reseller price list (not Royal Mail primary). [https://www.mailcoms.co.uk/current-royal-mail-postage-rates/]
- Typical seller shipping seen: free (most), re-delivery fee £5; one seller states postage separately; no consistent flat rate found. [https://www.reviewscard.com/products/google-tap-to-review-cards]
- PECR: email marketing to individuals needs consent, except "soft opt-in" for existing customers of similar products with an opt-out in every message; sole traders/some partnerships count as individuals; limited companies and LLPs do not. [https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guide-to-pecr/electronic-and-telephone-marketing/electronic-mail-marketing/]
- (inference) A "notify me when X launches" form is marketing: use an unticked consent box, store timestamp/wording, one-click unsubscribe, no soft opt-in because they are not customers.
- UK GDPR retention: ICO storage-limitation page returned 404 so not quoted. No fixed period found in sources; (inference) set a documented retention rule (e.g. order records for the accounting period HMRC requires; personalisation text deleted once order complete). Ask accountant for the period. **[REVIEW]** [https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/the-research-provisions/principles-and-lawful-basis/storage-limitation/]

## 6. Stripe Checkout facts (current docs)
- `shipping_address_collection.allowed_countries`: required array of two-letter ISO codes (GB is in the list). [https://docs.stripe.com/api/checkout/sessions/create]
- `shipping_options`: max 5; each takes `shipping_rate` (ID) or `shipping_rate_data` with `type: fixed_amount`, `fixed_amount.amount` (integer minor units, i.e. pence) and `.currency` (e.g. `gbp`), `display_name` (max 100), optional `delivery_estimate` min/max with units hour/day/business_day/week/month and value > 0, plus `tax_behavior`. [https://docs.stripe.com/api/checkout/sessions/create.md?query=shipping_options]
- `custom_fields`: up to 3; `key` alphanumeric up to 200 chars; `label.custom` up to 100; types text/numeric/dropdown; text `default_value` up to 255, optional min/max length; `optional` defaults false. [https://docs.stripe.com/api/checkout/sessions/create.md?query=custom_fields]
- Metadata: up to 50 keys, key names up to 40 chars, values up to 500 chars, no square brackets in keys, strings only. [https://docs.stripe.com/api/metadata]
- `line_items`: payment mode max 100; field accepts Prices; the fetched page did not expand `price_data`, so verify before building. [https://docs.stripe.com/api/checkout/sessions/create]
- `expires_at`: 30 minutes to 24 hours after creation, default 24 hours. [https://docs.stripe.com/api/checkout/sessions/create]
- `payment_status` values: `paid`, `unpaid`, `no_payment_required`; `status`: `open`, `complete`, `expired`. [https://docs.stripe.com/api/checkout/sessions/object]
- Fulfilment: webhook `checkout.session.completed` plus `checkout.session.async_payment_succeeded` for delayed methods; handler must be safe to run multiple times for the same session, retrieve the session, and check `payment_status`. Also handle `async_payment_failed`. [https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted]
- Shipping address on the session object is under `collected_information.shipping_details` (`address` {line1, line2, city, state, postal_code, country} and `name`). The old example object still shows top-level `shipping_details`: verify the pinned API version. [https://docs.stripe.com/api/checkout/sessions/object.md?query=collected_information]
- Idempotency: `Idempotency-Key` header on POST, up to 255 chars, keys pruned after 24h in API v1, same key with different params errors. [https://docs.stripe.com/api/idempotent_requests]
- (inference) Personalisation text (business name, Wi-Fi SSID, link, up to ~500 chars) should be collected on our own form first, saved server-side, and a short order ID put in `metadata`/`client_reference_id` (max 200 chars). Do not store Wi-Fi passwords in Stripe metadata. [https://docs.stripe.com/api/metadata]
